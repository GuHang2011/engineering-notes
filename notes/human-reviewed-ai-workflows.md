# AI 办公：让模型提建议，让用户做决定

把大模型接进办公系统后，最重要的产品边界不是生成按钮，而是生成结果会不会未经确认就改变业务数据或通知别人。

## 草稿与副作用分开

资料备注、催办消息、任务说明和演示稿都可以由模型起草，但保存、审批、发布或发送应继续由用户在业务页面确认。失败重试应保留已有输入与草稿，并通过请求标识或服务端幂等处理避免重复创建任务或发送两次消息。

页面清楚显示所选模型、处理状态和数据发送说明。生成内容应当可以编辑；事实和引用需要人工核验。模型返回“成功”并不等同于结果已持久保存。

## PPT 也是可继续编辑的办公文件

一键生成 PPT 时，把受众、场景、页数、配色和补充材料作为明确输入。导出后应能在 PowerPoint 或 WPS 中继续编辑，而不是只把整页截图贴成图片。失败时保留已有文稿和备注；下载失败时允许重新导出，不要强迫用户重新消耗模型额度。

浏览器中的草稿要按账号区分并提供清除入口。浏览器本地存储不是云端备份，也不能在公用设备上代替访问控制；密钥不能进入草稿。离开页面前，对未保存内容给出明确提示。

## 先定义数据规则

接入模型前，应确认哪些材料能离开校内服务器、第三方保留策略是否符合单位要求、用户能否选择服务商，以及日志要保留哪些最小诊断字段。不要记录完整提示词、附件全文、Authorization 头或 API Key 来方便排查问题。

进一步阅读：[DeepSeek API 文档](https://api-docs.deepseek.com/)。各服务商的数据处理、保留期、费用和地区政策可能变化，应以用户实际服务协议为准。
