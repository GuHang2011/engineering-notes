# 学校协作系统部署：先把边界和恢复方案想清楚

把一个校内办公系统部署到服务器，最容易低估的往往不是启动命令，而是配置、持久化、网络入口和故障恢复之间的关系。下面是我整理高校资料归档与协作系统时采用的检查思路。

## 入口与服务边界

让浏览器只访问 HTTPS 反向代理。静态前端、业务 API 和数据库分开放置；MySQL 只允许应用网络访问，不直接暴露给校园网用户。上传文件也不应成为绕开权限检查的静态目录。

反向代理的请求体限制应对应具体业务：普通归档可以按业务上限配置；大文件聊天传输应按分片请求，而不是试图让代理接受整个 1 GiB 文件。代理超时也要覆盖慢速磁盘和模型请求，但不应无限放大。

## 配置与持久化

- 数据库口令、初始管理员密码、AI 主密钥和服务地址放在受控环境配置中，不提交到仓库或前端资源。
- 需要持久保存的数据目录要映射到持久卷。容器重建不应删除数据库、归档文件、聊天文件或 AI 加密主密钥。
- 应用启动时对必需配置做校验，并记录不含秘密的服务状态，避免“容器启动成功”被误认为业务可用。
- 不要把上传目录直接公开映射为 Nginx 静态资源；下载必须经过身份、状态和资源权限检查。

## 备份不等于可恢复

数据库备份之外，还要核对文件目录和密钥材料是否匹配。用户 AI Key 如果使用外部主密钥加密，只备份数据库而丢失主密钥，密文将无法恢复。备份应复制到不同存储位置，并定期在隔离环境演练恢复。

升级前先备份数据库和持久文件，再部署新版本，检查后端日志、健康接口和关键用户流程。发生故障时回滚应用版本，不要用删除数据卷来处理启动错误。

## 上线前核对

1. 确认初始密码已修改，管理员权限范围符合学院边界。
2. 确认 HTTPS、反向代理、上传尺寸和超时配置。
3. 确认数据库端口没有暴露给终端用户。
4. 上传、下载、审核、公告、聊天、AI 连接测试分别完成一次端到端检查。
5. 确认数据库、文件目录和 AI 主密钥都能从备份恢复。
6. 监控磁盘、数据库连接数、错误率和备份结果，并明确值班责任人。

部署参数需要按实际服务器调优；单机开发环境的默认值不应直接视为生产建议。进一步阅读：[Spring Boot 外部化配置](https://docs.spring.io/spring-boot/reference/features/external-config.html)、[Nginx 请求体限制](https://nginx.org/en/docs/http/ngx_http_core_module.html#client_max_body_size)。
