# 浏览器兼容：验证失败路径比检查版本号更重要

声明支持某个浏览器版本，不代表实际文件上传、弹窗和下载都能正常工作。兼容清单应区分编译目标、自动化浏览器验证和真实设备验收，并明确每种状态。

## 项目验证边界

资料归档系统以 Chrome / Edge、Firefox 和 Safari 的较新版本为目标。在本地生产构建上，使用 Chromium、Edge 和 Playwright WebKit 验证了登录、上传、预览、下载、导出、AI 配置及 PPT 文件处理。Windows 上的 Firefox 测试进程受浏览器运行库问题阻止，真实 iPhone / iPad Safari 未做真机验收，所以这两项不能标成“已实测通过”。

这轮浏览器验证使用模拟业务 API 和模型响应，没有调用真实付费模型；PPTX 检查覆盖下载文件中的原生文字与备注，尚未完成 PowerPoint / WPS 内的最终排版验收。浏览器流程通过与真实服务商接入通过需要分别记录。

## 容易遗漏的行为

- **预览弹窗**：必须在用户点击仍处于浏览器授权窗口时打开窗口，再请求鉴权文件；否则容易被弹窗拦截。
- **文件下载**：不要假定脚本触发的下载在所有浏览器都成功。保留用户点击的下载链接，并正确释放 Blob URL。
- **浏览器存储**：隐私模式、配额不足或用户设置可能让存储读写失败；捕获错误并提示数据是否只在当前页面保留。
- **日期时间**：无时区字符串会被不同引擎和用户本地时区解释成不同时间，服务端和客户端应明确时区。
- **移动端**：检查短屏、软键盘、安全区域、触屏操作和下载文件位置；模拟视口不能代替真机测试。
- **辅助功能与动效**：保留键盘焦点和文本选择，支持 `prefers-reduced-motion`，避免动画成为唯一状态提示。

## 建议的验证表

记录浏览器和版本、操作系统、生产构建路径、真实或模拟设备、测试数据、是否调用真实服务，以及未验证的场景。手动重点覆盖弹窗被阻止、存储被拒绝、下载失败、网络中断和窄屏操作。兼容报告诚实标出“目标支持”“自动化通过”“真机通过”“未验证”，比一张绿色矩阵更有用。
