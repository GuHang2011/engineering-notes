# 个人 AI 接入：让密钥归用户所有

为办公系统增加模型能力时，我采用每个账号配置自己的服务商、模型和 API Key 的 BYOK（Bring Your Own Key）方式。它能明确费用和密钥归属，但也意味着输入内容会被发送到用户选择的服务商，界面必须在调用前说明这一点。

## 密钥生命周期

- Key 只在用户输入和服务端调用过程中使用；配置查询只返回“已配置”状态，不回传完整密钥。
- 不把 Key 放进 `localStorage`、页面草稿、下载文件、错误日志或 URL。
- 服务端存储时使用带认证的加密方式，例如 AES-GCM，并把密文绑定到所属账号；加密主密钥独立于业务数据库保存。
- 数据库备份和主密钥备份都需要受控保管。丢失主密钥可能导致已保存的 Key 无法恢复；轮换前先设计迁移和回退步骤。
- 用户更换模型服务地址时，不应无提示地把之前的 Key 发送到新地址。

## 用户提供的模型地址也是输入

允许自定义 API 地址会引入服务端请求伪造风险。应限定受支持协议和端口，拒绝 URL 凭据、内网/回环/云元数据地址及不受信任的重定向，并在实际解析连接地址时再次校验。设置连接与读取超时、每账号并发限制和输出上限；不要把任意 URL 直接交给 HTTP 客户端访问。

具体策略要根据允许接入的服务商设计和安全测试。只检查 URL 字符串而不约束 DNS 解析、重定向或代理行为，并不足以防护 SSRF。进一步阅读：[OWASP SSRF Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)、[DeepSeek API 文档](https://api-docs.deepseek.com/)。

## 生成结果要经过人工确认

模型生成任务说明、催办文案或演示稿时，把结果作为可修改草稿展示。用户确认后才保存任务、更新资料或发送通知。失败时保留已有草稿，重试应避免重复执行副作用。

模型额度、速率、可用模型和价格属于服务商账户规则。应用只能报告自己的请求状态，不能把 token 上限误称为余额查询，也不能承诺模型事实准确。涉及学生、教师或未公开材料时，应先确认学校数据规则是否允许把材料发送到第三方模型。
